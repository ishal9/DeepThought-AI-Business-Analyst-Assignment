# AI Business Analyst - Process Management Assignment

## Overview

This project is a structured diagnostic and systems design exercise based on a mid-scale API manufacturing company undergoing rapid operational scaling. The objective was to analyze execution breakdowns, identify behavioral and structural gaps, and design a scalable system that improves accountability, visibility, and operational control.

The solution combines process diagnosis, human behavior understanding, and lightweight system design using Excel-based tools.

---

## Key Problem Areas Identified

### 1. Lack of Ownership in Execution
Alerts and trackers exist but do not assign clear individual responsibility, leading to passive visibility instead of action.

### 2. Fear-Driven Reporting Culture
Root cause data is incomplete due to fear of blame, resulting in poor learning loops.

### 3. Absence of Daily Planning Structure
Work is not categorized or planned at a daily level, causing meetings to become reactive problem-solving forums.

---

## Solution Approach

The intervention focuses on:

- Shifting from department-level to individual ownership
- Introducing psychological safety for accurate reporting
- Creating structured daily execution visibility
- Separating planning, execution, and escalation workflows

---

## Prototype Description

An Excel-based Execution Tracker was built with:

- Task ownership mapping
- Planned vs unplanned work classification
- Escalation logic based on delay duration
- Department-level bottleneck tracking
- Dashboard for real-time operational visibility

This prototype simulates a lightweight execution OS suitable for scaling from 2 to 8+ projects.

## Key Insight

Operational inefficiency in scaling organizations is not primarily a tooling problem. It is a behavioral and structural alignment problem where visibility exists but ownership and psychological safety are missing.
